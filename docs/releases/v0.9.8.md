**After updating, approve your daily profile once.** The service now applies a daily profile only when it holds its own record that you approved it. A profile kept before this version has no such record, so the card stays at its own settings until you ask your agent to load the daily profile (`load_daily`) and choose Yes in the Clocktail dialog. The card report says "waiting for approval" until then.

The record is a receipt the service keeps under `%ProgramData%\Clocktail\Approvals`, which only administrators can write. `profile.json` and the saved profiles stay where they were and stay editable, but editing them no longer changes what the service puts on: a profile that does not match its receipt is not applied, none of its values are used, and what Clocktail holds goes back to the card's originals. Keeping, adopting or loading a profile, setting the daily power limit and saving a profile each write a receipt after your Yes; stock and deleting a saved profile take it away.

The service's confirmation no longer holds the card while it waits for you. Recovery after a driver reset, going back to the daily profile and trial writes carry on with the dialog open. Only one confirmation can wait: another request is refused at once instead of queueing a second dialog, and after a No there is a five second pause before the next one. After your Yes the service checks again that the card, the profile and the trial are what you were shown.

If the protected folder cannot be used, for instance because another account created `%ProgramData%\Clocktail` first, the service still starts. It runs without approvals: no daily profile goes on and none can be kept, trials, recovery and stock work as before, and the card report gives the reason. Running the setup again repairs it: a folder that is not administrator-owned is moved aside as `Clocktail.untrusted-…`, nothing in it is read, and a protected one is made in its place.

The agent's own confirmation in chat is still there, so a kept profile still takes two prompts.

1,658 .NET tests and the installer tests pass, with the GPU, the driver and the dialog simulated. The approval folder was created, a receipt written, read back by a fresh instance and removed at its real location on a Windows 11 machine, elevated, and the folder's permissions were checked there. The whole path through an installed service on a card (install, start, confirm, restart) was not run before this release.

Upgrade with `npx -y clocktail@latest setup` and restart the MCP client.
