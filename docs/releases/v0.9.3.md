The uncore tuner now stops when a failure record or driver-reset recovery is unconfirmed, and suppresses recommendations when final restoration is incomplete. Memory and uncore jobs share the same failure-confirmation rules.

- **Stop on an unresolved uncore failure.** A crash-record request with a missing reply, timeout or broken pipe ends the search before another trial is written. This includes requests lost before delivery and records committed successfully whose replies were lost. Explicit rejection also stops the search. The job still attempts normal cleanup; verify the original failure record and recovery before starting another job.
- **Wait for confirmed reset recovery.** A reset in any of the four A B B A runs releases the measurement lease before waiting for the service to recover. Unconfirmed recovery ends the search. A confirmed candidate failure can still be followed by other comparisons; a reset during an incumbent run ends the search even after recovery.
- **Keep the measured trial's identity.** Uncore status adds `failure_recording`, with `state` (`confirmed`, `rejected` or `unknown`), `detail` and `trial_id`. An unresolved failure ends the job as `failed`, resets `best` to `start` and provides no candidate to apply, including when an earlier comparison had found a winner.
- **Require complete final restoration.** Missing, rejected, partial or skipped cleanup also ends uncore as `failed`, resets `best` to `start` and reports recovery as incomplete. A successful performance confirmation alone does not produce a recommendation.
- **Consolidate shared code.** Session rechecks, failure confirmation, reset counting and phase telemetry summaries share their implementations. Two unused slowdown helpers were removed. Production C# code is 32 lines shorter while retaining each tuner's performance criteria and each phase's completion rules.
