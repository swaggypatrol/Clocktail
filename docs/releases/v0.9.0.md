Lab tests now start from the tuning goal, and the memory tuner separates its scan boundary from a measured recommendation.

- **Choose the test goal.** `lab_test` defaults to the core profile: 30 s burn, 60 s solo at the high point and 60 s heavy/light leap. The memory profile runs 60 s memory + 30 s latency; uncore runs 30 s L2 + 30 s memory; all runs the six phases for 270 s. Each important phase gets its own time. Explicit `phases` still supports the old equal split (60 s when no duration is supplied), plus individual schedules such as `burn:30,solo:60,leap:60` with `seconds:150`. A bare `seconds` argument now applies to the default core profile, whose minimum is 150 s.
- **Missing clocks establish nothing.** A memory sweep requires actual measured memory clocks and usable bandwidth/latency. Missing readings, an offset that did not take effect, shared measurements and unfinished comparisons cannot produce a stable step or a recommended offset.
- **Recheck a suspected slowdown.** Two slower scan steps trigger an A B B A comparison before ending the scan. A lucky earlier reading or heat drift that does not reproduce no longer cuts the scan short. The original readings and paired rechecks are kept separately.
- **Compare candidates, then confirm.** The tuner shortlists up to three offsets, compares them A B B A against the daily offset, and independently confirms a winning change. Equivalent measured performance prefers the lower offset. The memory and uncore tuners share the paired-metric calculation. A disturbed comparison retries once; an interrupted or still-unjudgeable comparison names no best.
- **Read the result precisely.** `lab_status` reports `edge_mhz`, `candidate_mhz`, raw `comparisons`, and `confirmed`; `best_mhz` appears only after confirmation and verified restoration. A failed restoration leaves the job failed with recovery guidance. `tune_memory` reports a scan-time estimate separately from the additional comparison work.

NVIDIA nvgwls, custom light/pulse loads, graphics testing and real-game observations remain available for their different coverage. The recommended workflow is targeted screening, paired confirmation of a few candidates, then repeatable game or application validation. Nothing is made daily automatically.

Validated with simulated workloads and broker/measurement-process tests; this release does not claim new GPU hardware coverage or a measured tuning speedup. See [the Lab guide](https://github.com/swaggypatrol/Clocktail/blob/v0.9.0/docs/lab.md) for budgets, result fields and compatibility.

Upgrade: `npx -y clocktail@latest setup`, then restart your agents. Setup installs the MCP server, lab and broker together; profiles and history remain in place.
