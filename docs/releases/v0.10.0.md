# Clocktail 0.10.0 release notes

Changes since v0.9.9 (`e71db00`) through `6060904`. The default MCP workflow now lets you select a V/F point, run a checked workload and see how often the GPU reached that point. Hardware tuning targets GeForce RTX 50 on Windows x64. [Compare the two revisions](https://github.com/swaggypatrol/Clocktail/compare/v0.9.9...60609043a9488059521ca87a5182a96ae5f638a2)

## What changed

| Area | Change and effect | Commits |
| --- | --- | --- |
| MCP and setup | The default lists 23 tools, including `lab_test`. Use `--full` or `CLOCKTAIL_TOOLS=full` for all 55. Setup preserves an explicitly selected mode. Discovery and the manual work even when the GPU cannot be opened. | [Discovery](https://github.com/swaggypatrol/Clocktail/commit/a431f7608) · [Setup](https://github.com/swaggypatrol/Clocktail/commit/281c77dbb) |
| GPU selection and C01 | The lab and its NVML sampler use an exact device match. With several CUDA devices, select the intended PCI address. The C01 FP32 workload keeps its CPU oracle and report format while dropping unused scan and worker-protocol code. | [Lab changes](https://github.com/swaggypatrol/Clocktail/commit/cd0d692f0) |
| V/F measurements | Pass a point index from `curve_around` as `lab_test.targetPoint`. Each phase reports `paired_samples`, `target_samples` and its three most frequent observed voltage/clock pairs. Zero target hits means all valid pairs missed. A null count means the target or paired readings were unavailable. The tuning log keeps the target and counts by phase. Polls include CPU checks and pauses. | [Measurement](https://github.com/swaggypatrol/Clocktail/commit/7b649318e) · [Persistent log](https://github.com/swaggypatrol/Clocktail/commit/5e2fc9551) |
| Game coverage | Near-top time uses the highest starting-curve frequency within the measured NVVDD limit. On the RTX 5080 reported in issue #19 that reference was 3,195 MHz. The unreachable 3,562 MHz point had made the old report show zero. A missing reference now gives unknown coverage. | [Game change](https://github.com/swaggypatrol/Clocktail/commit/6e2e5175d) · [Hardware report #19](https://github.com/swaggypatrol/Clocktail/issues/19) |
| P0 writes and recovery | Core and memory P0 writes can also change the effective Core curve. The broker journals the original controls and verifies coupled changes against readback. An unverified rollback retains the recovery record. Restoring a regional daily profile with a Core P0 offset and no explicit curve checks the per-point displacement. Partial restores report the omitted settings and their readback. Drivers without a V/F info slot can verify the raw P0 value only. | [Broker change](https://github.com/swaggypatrol/Clocktail/commit/3fee4a54c) · [Game recovery](https://github.com/swaggypatrol/Clocktail/commit/6e2e5175d) · [Original contribution #18](https://github.com/swaggypatrol/Clocktail/pull/18) |
| Installer and CI | Windows PR builds produce an installable npm tarball stamped with the tested revision. The setup plan runs the installer that produced it. `verify` compares all six installed payload files with that package. | [Packaging](https://github.com/swaggypatrol/Clocktail/commit/281c77dbb) · [Install instructions](https://github.com/swaggypatrol/Clocktail/commit/fcecaf898) |
| Broker shutdown | The closing thread enforces the worker-drain timeout directly. A blocked worker keeps its native resources until it finishes. | [Shutdown fix](https://github.com/swaggypatrol/Clocktail/commit/1f668a8f6) |

## Roll back an installation to v0.9.9

1. Finish active jobs, or stop them with `lab_stop` and check `lab_status`. End any tuning session. Let the current broker complete pending write or game recovery and verify the restored settings. A pending `game-recovery.json` can contain a null `TopMhz` that v0.9.9 cannot read. Keep the record and its backup in place until the current broker finishes recovery.
2. From an interactive Windows PowerShell, run the pinned installer and select your clients. Approve the broker installation so the MCP server, lab and broker all come from the same package. The in-place setup preserves profiles and logs.

   ```powershell
   npx -y clocktail@0.9.9 setup
   ```

3. Restart the MCP client, run `npx -y clocktail@0.9.9 verify`, then use `card_report` to compare the selected GPU and effective curve with the saved baseline. This matters especially for a daily profile that relies on a Core P0 offset. In v0.9.9 the default tool list is full and `--lite` selects its smaller list.

## Roll back the source

The first-parent merge for the V/F, MCP and installer changes is `14b84b0`. The independent broker shutdown fix is `6060904`. To undo only shutdown, revert the second merge. To undo both, start a branch from current main and revert them newest first. [PR #21](https://github.com/swaggypatrol/Clocktail/pull/21) · [PR #22](https://github.com/swaggypatrol/Clocktail/pull/22)

```sh
git fetch origin
git switch -c revert/vf-workflow origin/main
git revert --no-edit -m 1 6060904
git revert --no-edit -m 1 14b84b0
dotnet test tests/Clocktail.Tests -c Release
node --test npm/test/clients.test.js
```

Review the resulting diff and run Windows and Linux CI before merging the rollback.
